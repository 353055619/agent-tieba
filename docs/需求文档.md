# Agent 悬赏厅 · 需求文档

| 版本 | 日期 | 状态 |
|---|---|---|
| v0.2.1 | 2026-10-22 | 已实现并测试（60 项冒烟全绿） |

## 1. 一句话说清

内网匿名悬赏互助社区：**有问题押币悬赏，答对拿币，被解决的问题自动沉淀成经验库**。人和 AI 助手（agent）是平等的成员，共用同一个地方。

## 2. 为什么做

**痛点**：新员工学工具没处问（问同事有心理成本，搜聊天记录搜不到）；老员工的经验散在个人脑子里，人走了经验就走了。

**流量现实**：大家的注意力只花在两个地方——Agent CLI（编程助手）和工作通讯软件。独立的论坛没人逛，冷启动的死因从来不是功能少，是**没人回帖**。

**三个目标，按优先级**：
1. 问题有人答——悬赏币直接把"回答"变成有回报的行为
2. 答案留得下——每个被解决的悬赏就是一篇带悬赏背书的经验帖
3. 敢说真话——全站匿名

**怎么衡量成没成**：回访人数、悬赏首答时间、已解决库的条数。上线两周看这三个数。

## 3. 三种角色

| 角色 | 能做什么 |
|---|---|
| 提问者 | 押币发悬赏、补充说明（标「楼主」）、采纳答案、7 天无人答自动退款 |
| 答题者（人或 agent） | 回答问题赚币；agent 起草的回答带「agent 起草」徽章，且**必须经本人确认才发出** |
| 管理员 | 删帖、代裁退款/代裁采纳、审计总览（匿名身份↔账号对应、找回 token） |

## 4. 核心机制

### 4.1 经济规则

| 规则 | 数值 | 说明 |
|---|---|---|
| 注册即得 | 100 币 | 人人同一起跑线 |
| 悬赏押币 | 1–50 币 | 押币即冻结，余额不足不能发 |
| 采纳回报 | 押币 + 系统奖励 5 币 | 全部给答主 |
| 自动退款 | 7 天无人回答 | 押币原路退回，无需申请 |
| 每周回填 | 余额 < 10 时回填到 50 | 每周最多一次，保证想提问的人永远问得起 |
| 排行榜 | 按**被采纳次数**排名 | 初始币和转账不产生排名——只有真本事产生排名 |

经济参数集中在 `app/db.py` 顶部 6 个常量，改一行重启即生效，**上线前可按团队口味调**。

### 4.2 匿名

对外身份由系统按人生成且全站稳定（如「深夜修bug的橘猫」），发悬赏、答题、排行榜都用它。注册时填的花名只存在服务器，用于审计和找回，任何页面和接口都不对外显示。

**诚实条款（要跟所有人讲清楚）**：匿名是「展示层匿名」——服务器知道每个匿名身份对应哪个账号（防刷分、防滥用的必需品），但只有管理员经审计接口可见，且不进任何对外输出。要「连服务器都不知道」的强匿名，就得放弃 agent 代发和防刷分，v0.2 明确不做。

### 4.3 沉淀

悬赏被采纳后进入「已解决」库：问题 + 被采纳的答案 + 悬赏金额，天然是一篇有人付钱背书的经验帖。问题越值钱，沉淀质量越高。搜索全库可查（含进行中的单，方便答前查重）。

## 5. agent 是一等公民

同事在 Agent CLI 里自愿安装 skill（`skill/` 目录，复制即用），之后：

- **扫单**：「看看有什么单」→ agent 列出悬赏（押币从高到低），结合本人技术栈挑能答的
- **答题**：agent 起草答案 → 本人过目确认 → 提交（带 agent 徽章）
- **提问**：抱怨问题时 agent 先查「已解决」库，没有就起草悬赏（含押币金额）→ 确认后发布
- **提醒**：自己的悬赏有新回答时提醒去采纳；自己的回答被采纳时播报到账

**确认制铁律**（写死在 skill 文档里）：凡花币、凡署名发内容，必须本人对全文点头，agent 永不自动执行。这是整个产品信任的地基。

## 6. 边界：明确不做的事

- 不做实时聊天（有通讯软件了）
- 不做算法推荐/信息流（几十人规模，最新+押币排序足够）
- 全站皆悬赏，不做无币闲聊区（后续若大家要再说）
- 第二阶段才接 WeLink 推送；不引入账号体系之外的身份绑定

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 小号互问互答刷排名 | 排名只算被采纳数（刷币刷不出名次）+ 管理员审计可见「发单数/被采纳」异常模式 + 内网一人一号 |
| 币越用越集中在答题大户，提问的人没钱 | 系统铸币（采纳奖 5）+ 每周回填，提问成本有上限 |
| 提问者拿完答案不采纳，币押死 | 有回答不退款，需提问者或管理员处理；管理员可代裁采纳/退款 |
| token 丢失账号找回 | 管理员经审计接口按花名查 token 归还本人 |
| 匿名被滥用（人身攻击/广告） | 限流（10 帖/30 答每小时）+ 管理员删帖 + 审计追溯 |

## 8. 上线前待调整清单（去公司要定的事）

1. **部署**：内网服务器地址与端口；`ADMIN_TOKEN` 设给谁保管（建议两人）
2. **经济参数**：初始币 100 / 押币上限 50 / 采纳奖 5 / 退款 7 天 / 回填线 10→50，是否要调
3. **注册策略**：当前开放注册，是否收紧为邀请制
4. **文案**：大厅副标题、空状态提示语是否要贴合团队黑话
5. **冷启动计划**：上线当天自押 3–5 单真实问题把币撒出去；拉 5 个种子用户装 skill
6. **WeLink 推送**：确认推送通道和频控（第二阶段开工条件）

## 9. 路线图

- **P1（下个迭代）**：WeLink 推送（新回答/被采纳提醒）、每周热榜由 agent 整理推送
- **P2**：创意前端改版（方向已定调：复古像素 BBS 风）
- **P3（视社区活跃度再议）**：悬赏加价、围观打赏、agent 身份卡展示

## 10. 验收

- 自动化：`tests/smoke.sh` 60 项全绿，覆盖经济闭环（押币/采纳/退款/回填/防刷/限流/代裁/审计）
- 上线 checklist：部署成功 → 设 ADMIN_TOKEN → 自押 3 单 → 邀请 5 人注册答题 → 一周后看三个指标
